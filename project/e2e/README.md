# Real Codex E2E

## Acceptance protocol (Round54)

`artifact` is an additional non-UI scope for documentation, architecture/knowledge, workflow evidence and test/build scripts; independent delivery review owns those checks. `cross-boundary` refers specifically to UI/API state consistency. To avoid shell interpretation of source quotes, clients also accept `@/absolute/path/to/request.json` (author this JSON only in the agent's isolated scratch).

Stage budgets are declared once in `ui-contract.ts`: scenario preparation 6 minutes, unchanged browser review 13 minutes, protocol correction 2 minutes, plus 1 minute of owner overhead. The lease covers the sum. Scenario maps group same-channel obligations rather than rewriting the specification; rejected entries identify their exact ID/source. These budgets bound real work, not automatic business retries or a reset of past attempts.

Before browser grading, a fresh AI scenario planner reads the complete original request and acceptance. It declares source-quoted requirements as API, UI, cross-boundary, artifact or genuinely unspecified, plus a finite list of necessary setup capabilities. The host admits only contract-declared HTTP routes/methods on the leased localhost origin, serializes and deduplicates requests, bounds their number/deadline, rejects redirects/traversal/unknown capabilities, and seals/closes setup before UI review. Account/admin fixture setup mutates only the isolated app runtime state. There are no generated-app-specific endpoints, selectors, data or business assertions in the harness. Preparation responses are never UI proof; missing/failed setup is not feedback to the implementer.

The independent UI reviewer gets the frozen scope plan. API-only requirements (including eventual state transitions) cannot justify invented UI controls. General delivery of both a UI and an API does not require every API feature to be exposed as a button. Unresolved scope cannot silently pass, and actions/findings refer to explicit UI/cross-boundary requirement IDs. Missing coverage is scope-unresolved, not repairable by receipt formatting. Snapshots default to full-page; absence claims require full-page evidence in the relevant state. Dispatch success is not an asynchronous outcome: derive bounded waits from requirements, then observe again. Argument/pre-dispatch rejection, stale refs, predicate-not-met, unknown effects and lost control have distinct structured diagnostics. Only known safe re-observation is recoverable; generic CDP/deadline/late effects still fence, without replay.

Successful native snapshots have observation IDs. Reference those in action/finding evidence rather than rebuilding escaped quotations. Admission resolves them against protected owner logs for this session/origin; failed snapshots, command inputs, preparation responses and foreign observations are rejected. Legacy quote-based receipts remain readable. The shared action contract is used by prompts, admission and controller.

Proposal admission is preflighted before official submission. A format/evidence-reference error permits **one** protocol-only correction using a read-only observation catalog after browser/setup capabilities are closed. Status, findings, action coverage/url/target/expected are frozen; no business actions, application changes or business-attempt reset are allowed. Correction invocations/usage and diagnostics are retained separately. Unrecoverable protocol or scope errors remain nonpassing infrastructure results with `failureClass=protocol-cost|scope-unresolved`; they never trigger implementation correction. A successful admission can still be a genuine business FAIL.

Actions separate their unchanged human-readable `coverage` claim from canonical `requirementIds` in the sealed scope plan (singular `requirementId` remains compatible). One observed action can cover several original obligations without duplicating browser actions. Legacy exact-ID coverage, unambiguous `ID: description` / `ID — description`, and leading ID lists remain compatible. Missing canonical IDs may be supplied during the one representation-only correction; existing IDs and all business claims stay frozen. Contradictory references, API/artifact claims relabeled as UI, and genuinely untested requirements remain rejected.

The current-version suite owns the shared runner and independent acceptance. Root `../../e2e/run.ts` now selects the explicit pre-refactor product adapter; its historical request/fixture files remain available, but old shell runners delegate to the shared harness rather than the historical deterministic business scoring. Both products use the exact same `cases/*/request.md` and `acceptance.md` bytes. Only version-owned installation and operation routing differ; the legacy adapter overrides current routing prose, never business requirements. There is no implicit legacy/global fallback.

`--product=current|legacy` records the selected product in provenance. Legacy means a run-local `codument` binary plus its authentic project-local codument-* Skills/std, while current means run-local `depa-codument` and its authentic global App Skill. The other executable name is a rejecting sentinel in each run. All controllers recover profile identity from provenance. Compare a compiled frozen pre-refactor release against the compiled latest dirty snapshot, not against a renamed binary or manually copied current guidance. Phase elapsed times aggregate actual receipts including failures; independent raw session token accounting remains unchanged.

Run only from a copied repository under `/tmp`, with a candidate built by that copy's `scripts/build.ts`. There is no default global or legacy binary fallback:

```sh
bun test e2e
bun e2e/run.ts smoke --bin=/absolute/tmp/depa-codument-candidate
bun e2e/run.ts ui-probe --bin=/absolute/tmp/depa-codument-candidate
bun e2e/run.ts probe --bin=/absolute/tmp/depa-codument-candidate
bun e2e/run.ts review-probe --bin=/absolute/tmp/depa-codument-candidate
bun e2e/run.ts run todo --bin=/absolute/tmp/depa-codument-candidate
bun e2e/run.ts report /private/tmp/depa-codument-e2e-<run> ...
```

Order: smoke → todo → stream-pipeline-ai-agent → blog → ecommerce → nested-mission-agent → second independent todo and stream runs. Each invocation creates a unique retained run root; do not rerun a still-active invocation. Up to three attempts per run retain first-attempt failures. Planning and implementation are separate fresh Codex sessions that recover from workspace files; each correction also opens a fresh session rather than relying on warm conversation history.

After changing reviewer transport, `review-probe` calibrates the same read-only agent turn, native execution observer and verdict gate with a tiny new Python fixture before spending a full business run. It makes one bounded real Terra call; it is not a no-model smoke or business acceptance, and cannot promote/resume an old trial. Reviewer guidance explicitly requires a successful standalone test call: a pytest success hidden inside a subsequently failing diagnostic block is not an admitted successful execution. Unsupported control flow/heredocs remain rejected rather than heuristically treated as PASS.

After planning validation, the parent records `planning-handoff.json` with repository, authored resource ID, lifecycle path and observed source hash. Each implementation session receives these exact identities and reobserves them with `track context`; default `list` intentionally remains active-only. Status/path changes are allowed, identity loss/duplication/replacement is rejected. This fresh-case handoff is not a second lifecycle owner, approval receipt or cached semantic verdict. New optimization batches use new run roots and retain all earlier failures and limits.

`e2e/workflow-policy.json` owns the benchmark's explicit Track hook choices (`GapLoop`, `AttractorCheck`, `HumanConfirm`). Default is `enabled: false` for all three, matching product auto (do not hang them). Flip a flag and keep the attribute template to require that check. `workflow-policy.ts` loads that file and supplies the same declaration to planning, implementation and independent review. Each run preserves `workflow-policy.json`; planning and post-implementation admission check the actual typed hooks, including backlog declarations without executing unselected work: enabled kinds must appear exactly once on the final first-level TaskGroup `phase:after`, disabled kinds must not appear. Product auto defaults are unchanged. A matching declaration does not prove fresh execution: the implementation still runs enabled hooks and the independent reviewer checks their evidence. Resume rejects absent or different policy snapshots instead of silently applying new choices to an old trial. Reports expose the recorded policy; older rows are null, not implicitly equivalent. Configuration-file equality alone does not guarantee equal checks because the authored Track may select none.

Before a stream model turn, the macOS runner discovers an existing managed Python 3.12 using `~/.local/bin/uv`, with downloads disabled. It verifies execution within the sandbox, records executable hashes in `python-runtime.json`, and creates only per-run executable wrappers. No host installation is changed. Missing runtimes fail before a model call; resume rejects runtime drift. Reviewers place new scratch environments under their isolated `HOME/tmp`, not in delivered source.

`run ... --resume=<run-root>` verifies binary and immutable case identity, rejects a live owner, retains earlier attempts and elapsed time, and cannot reset the three-attempt budget. Resume is not a first-pass or denominator reset. Framework-invalid pilots are separately excluded with an auditable reason; their token costs remain visible.

The three outer attempts do not override configured workflow stops. Delivery is observed from Track completion, validation, tests and hook receipts; the chat message is not a JSON envelope. An exhausted `on_exhausted=block` hook ends that case as blocked, with no automatic retry/resume. A parent-owned terminal-policy receipt preserves any controller interruption's raw result while counting the actual workflow block as nonpassing business delivery, not excluding it as a transport failure. Continue other independent cases without resetting this case's hook budget.

An independent stop guard also reads CLI-owned round state, configured limits and terminal reports before accepting delivery or retrying, so a false delivered claim cannot override an observed singleton exhausted block. The product currently has a resource-level counter and free-form scoped reports, not scope-bound machine receipts. Multiple exhausted scopes with incomplete/mixed report evidence therefore yield explicit harness-unsupported, not a business-block assertion; complete unambiguous NO_GAP reports are accepted.

`E2E_AGENT=codex|eidolon` selects the runtime (`e2e/agent-runtime.ts`). Codex is fixed to `gpt-5.6-terra`, effort `medium`. Eidolon defaults to `deepseek-iqingwa/deepseek-v4.1-flash` (`E2E_EIDOLON_MODEL` overrides). Observed child session contexts must match the invoked identity. No quota purchases. Credentials are copied only into a private temporary auth file and removed when the invocation finishes; after an uncatchable kill, remove that one exact auth file manually. Personal config/plugins/Skills are not copied. Use `--auth` to choose an alternate existing auth file without printing it.

Eidolon has no `--output-schema`. Do not treat the model's dialogue or `last.md` as the delivery or review envelope. Implementation is admitted from workspace facts. Independent review writes a JSON verdict to isolated `HOME/tmp/<name>-verdict.json`; that file is the only review contract (Codex `--output-schema` last.md is a fallback only).

The mandatory macOS Seatbelt boundary keeps delivered source and workflow state read-only for reviewers. Agent scratch/proposals stay under isolated HOME/tmp; only the harness writes official receipts. Ego's `nodejs` executes remotely in its browser NodeService, so sandboxing the CLI alone does NOT sandbox arbitrary remote Node code. Reviewers are denied execution of the Ego binary (including its realpath) and use the restricted channel below. Only the trusted harness worker loads Ego's APIs. No OpenCLI or Chrome fallback is used.

UI automation uses Ego Lite. The owner creates one TaskSpace and passes `E2E_EGO_SPACE_ID=<id>`; every probe and serial fresh UI agent resumes that same space/p1. Never create a replacement space on failure or claim user control. The owner finishes the space exactly once on successful completion. `ui-probe` verifies only a harness-owned fixed fixture inside the acceptance sandbox, without a model: navigate, observe, input, click and observe the actual result. This is an infrastructure calibration, NOT a test script for any generated app. OpenCLI source and installation are not changed.

`browser-owner.ts` starts a single persistent Ego connection per acceptance phase. `browser-channel.ts` owns a serialized command queue and retained dialog projection; the worker gathers native receipts/events across independent client calls. The AI chooses `goto`, `snapshot`, `click`, `fill`, `selectOption`, `press`, waits and dialog responses through the generated `browser-client.ts` command. No arbitrary JavaScript/eval/fetch/CDP or application business scripts are exposed. Duplicate request IDs do not repeat effects; native timeouts fence later mutations rather than retrying uncertain actions. A pending dialog returns its real message immediately instead of running a blocked snapshot. User control stops the channel; no automatic claim/replacement.

Native dialogs are part of tool calibration: explicit prompt text, follow-on dialog messages from documented `page.events()`, and a final visible result. Three rounds use separate CLI calls for both prompts and verify duplicate answers are not replayed. The fresh agent decides prompt answers from real messages and requirements; it must not blindly accept chained dialogs or attribute its own invalid input to a product defect. Findings separate explanatory prose from `findingEvidence` snapshot excerpts; legacy quoted/JSON-escaped excerpts remain checked against actual native output. Command arguments cannot become observations.

Setup alone can write the temporary home to install the Skill. All candidate invocations, including setup/query/validation, use Seatbelt. Personal-home content reads are denied except explicit installed runtime directories; metadata reads are allowed so Node can resolve its executable. Application verifiers cannot read the temporary Codex state/auth. The trusted Codex host necessarily reads its temporary credential; this is not a separate credential boundary between Codex and its own tools. Network remains available for the model and dependencies.

All setup/agent/verification commands have logs and bounded lifetimes. Ordinary commands release their process groups. Ego workers instead receive an owner-authenticated close and end their NodeService lifetime; killing the CLI wrapper is NOT proof of worker release. Owner heartbeat loss triggers a watchdog shutdown. A successful fixed-fixture run must leave no reachable worker endpoint. Global `codument` and `depa-codument` installations are never rewritten. Each run copies the candidate and installs its global Skill into a temporary home; business assets remain `workspace/codument/`. The old `codument` command is a rejecting sentinel, not an alias.

Independent acceptance keeps runtime/installation identity, strict workflow evidence, delivered test/typecheck/build execution and fresh semantic review. The default runner no longer invokes fixed generated-business API/DOM/stream/nested oracle scripts. Historical oracle modules remain for historical evidence/tests, not current business admission. The fresh reviewer derives functional checks from complete requirements and the delivered implementation; fresh UI acceptance derives its own actions and expectations from requirements and live snapshots. Do not count self-authored tests or completion prose as independent acceptance. Provenance/report records `fresh-agent-semantic-v1`; legacy-policy rates are not a same-policy comparison.

Mutable runtime facts use a harness-owned per-phase `E2E_DATA_DIR` under isolated `HOME/tmp`; `DATA_FILE` provides a JSON store path. Apps honor this environment at server startup. HTTP, browser, nested servers and agent checks use distinct state directories. This separates databases/queues from delivered source without exempting ignored source, dependencies or `dist/`. Stream verification dependencies are installed before the delivered fingerprint is frozen; app scripts and business verification must then preserve it. Fresh-app archive checks confirm each promoted registry member matches its delivered owner/content; this is not a general historical merge oracle.

Archive promotion correlation currently admits a singleton archived delivery per repository. Multiple archived deliveries return explicit harness-unsupported/infrastructure status, not a business FAIL or PASS: reconstructing successive historical merges requires baseline-aware verification. Earlier completed validation remains evidence of its recorded harness only.

HTTP cases additionally stop at an `awaiting-ui` event. The runner owns an immutable request and starts the documented controller process (`controllerCommand`) unless `E2E_UI_CONTROLLER=external`. That separate process claims the exact request with a private lease, starts exactly one isolated app process, proves `/health`, then records `server-ready`. The runner still cannot lease a server. A controller that exits before leasing is an immediate infrastructure failure.

After `server-ready`, the runner claims the operator, starts its persistent channel, and launches a fresh Terra acceptance agent. It reads complete request/acceptance and the channel's narrow operation contract, then independently decides concrete operations from the actual page. No business selectors/actions/expected text are embedded in the harness. Admission reads harness-owned native worker logs for the assigned numeric TaskSpace, leased origin, real interactions and successful snapshots; it does not infer execution from the agent's shell strings. Historical shell parsers are retained only for historical replay/unit fixtures. Receipt checks validate evidence provenance/shape, not business semantics. Snapshot output supplies observed facts, never command inputs or action-dispatch success alone. The agent writes only an advisory proposal under isolated HOME/tmp; the harness admits/rejects it. Missing tools/control/receipt is infrastructure, a reproduced business defect is failed. Stop on user control; no fallback.

`E2E_UI_OPERATOR=1` means a person is already attached; the agent does not start, and the 15-minute evidence clock starts. `E2E_UI_OPERATOR=wait` means a person will attach: the agent does not start, and a missing claim within 15 seconds is still infrastructure. `E2E_UI_CONTROLLER=external` leaves both the controller and the operator to the caller. Those flags are for someone who is watching. Never synthesize a UI PASS. The generated application and coding agent cannot write any of those root records.

```sh
# Starts the controller and prints origin, attempt and lease only after /health succeeds.
bun e2e/run.ts ui-server /private/tmp/depa-codument-e2e-<run> --bin=/absolute/tmp/depa-codument-candidate
# Submit a typed observation from the independent browser operator.
bun e2e/run.ts ui-receipt /private/tmp/depa-codument-e2e-<run> --bin=/absolute/tmp/depa-codument-candidate --receipt='<JSON>'
```

Actual UI defects, bare HTML and mismatched evidence reject acceptance; never synthesize a PASS from source inspection or the implementation agent's claims. A missing lease/start, failed health check or missing post-ready receipt is a controller infrastructure failure and does not ask the model to repair the application. Browser acceptance failure carries observed findings and remains a business correction. Historical `infrastructure-failed` Todo and Blog applications may instead be examined once with `ui-reverify <historical-run-root>`: it creates a new temporary, read-only controller root pointing at the frozen application workspace. It never changes the historical run, source tree, result, attempts, usage or first-pass statistics; reports list that result separately as `uiReverifications`.

Results and JSONL usage live outside the writable business repository. Report first-pass and corrected-pass rates separately; infrastructure failures and incomplete runs are excluded and explicitly counted. Token counters are observed Codex counters, not estimated currency. Missing counters remain null. Child-session cost coverage must be stated rather than silently undercounted.

Codex UI proposals use `--output-schema` and the host-owned final output file as the single advisory transport. A tool's file-change claim is not proof of a file on disk. Other runtimes retain the explicit advisory-file transport; missing/malformed output is protocol-cost infrastructure, never a guessed verdict. Typed output does not establish a PASS: the same native-log, leased-origin and scoped-evidence admission remains mandatory. One format-only repair retains the original judgement and cannot rerun business actions. Exact native pointer-interception refusals allow re-observation, not forced input or mutation replay; unknown deadlines and explicit late-effect flags still fence the channel. The fixed-fixture preflight verifies that intercepted input dispatched no change and that the worker really closed.

Selection data is not guessed by the harness: the reviewer chooses it from live controls. Native strings, option descriptors, arrays and clearing are preserved. An exact missing-option refusal is recoverable only for a single string selection; arrays/descriptor failures are not assumed free of partial effects. Late-effect flags, after-dispatch errors and unknown deadlines retain priority. Empty fill/selection strings were already supported and now have explicit native calibration. A protocol repair after a formal trial ends is a separate read-only reverification, never a reset of that trial's attempts, timing, costs or result.

An exception class is not evidence of dispatch phase. Harness validation errors occur before Page invocation; only the complete calibrated native click-options diagnostic is additionally admitted as safe SDK argument rejection. Unknown native TypeErrors, wrong-operation or appended diagnostics remain uncertain mutation failures and cannot authorize a replay.

Reports prefer per-response raw session usage (deduplicated by response ID), including child and interrupted turns. Completed top-level totals are shown separately, never added again. Session coverage counts are observations, not a guarantee that the provider exposed every billed token; currency cost stays null.
